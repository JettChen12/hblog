这是本站的第一篇文章，记录三件在建站之前就定下来的事。它们决定了这个博客长什么样，也决定它不长什么样。

> 千里之行，始于足下。这个站的名字叫 H-BLOG，站训是这句老话——一个像素旅人会替它在首页走下去。

## 一、为什么是纯静态

博客的内容主体是文章，文章是写出来的，不是「提交到数据库」出来的。所以发布流程是：

1. 本地用 Markdown 写文章；
2. `git push` 推到仓库；
3. CI 构建成纯静态 HTML，同步到服务器；
4. 服务器上只有 Nginx 和静态文件。

没有数据库、没有后台、没有常驻进程，攻击面基本为零，服务器资源占用可以忽略。选 Astro 是因为它构建出的页面默认零 JavaScript：文章页在浏览器里就是一份完整的 HTML，脚本挂了也照样能读。

写一篇文章的开头只需要一个 frontmatter：

```yaml
---
title: 文章标题
description: 一句话摘要，列表页和搜索都会用它
pubDate: 2026-10-25
tags: [建站, Astro]
---
```

## 二、像素风要克制

像素风是这个站的皮，不是骨。定了几条硬规矩：

| 规矩 | 原因 |
| --- | --- |
| 点阵字体只用于标题与界面元素 | 中文长文用点阵读起来累，正文交给系统字体 |
| 全站一个签名动画 | 首页那个走路的旅人，别的地方不再加戏 |
| 硬边、直角、单色描边 | 圆角和投影模糊会立刻破坏像素语言 |
| 色彩只有一支信号色 | 珊瑚橙只给链接、焦点、当前项，不做大面积铺陈 |

配色血统来自 [Sweetie 16](https://lospec.com/palette-list/sweetie-16) 调色板：深蓝墨做纸面，珊瑚做信号。这套关系在像素游戏圈被验证过十几年，比凭空配色可靠。

## 三、给自己立性能预算

静态站很容易做出很快的页面，也照样能塞慢。所以一开始就把预算写进需求：

- 移动端 Lighthouse 性能分不低于 95；
- 最大内容绘制（LCP）小于 2 秒；
- 首页关键路径 JavaScript 不超过 40KB；
- 首屏字体实际下载不超过 150KB。

最后一条最棘手：中文点阵字体全量有好几兆。解法是把字体按 `unicode-range` 切成几十个小包，浏览器只下载页面真正用到的那些切片。你在这一页看到的标题字体，实际传输量是两位数 KB。

这三条规矩会一直挂在这个仓库的需求文档里。后面每一篇文章，都算这段路上的一步。
